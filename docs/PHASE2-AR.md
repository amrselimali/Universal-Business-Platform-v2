## 1. القرارات المعمارية المعتمدة

| # | القرار | التفصيل |
|---|---|---|
| D1 | **شركة واحدة لكل قاعدة بيانات** | لا يوجد `tenant_id`؛ العزل على مستوى الفرع كما في المرحلة 1. دعم تعدد الشركات يحتاج ترحيلًا مستقلًا + RLS ويُؤجَّل حتى قرار المالك |
| D2 | **ترقيم المستندات لكل فرع وسنة** | `document_sequences` بنطاق `(doc_type, branch_id, year)`، و`branch_id = NULL` يعني عدّادًا مركزيًا على مستوى الشركة، مع `number_padding` و`prefix` |
| D3 | **محرك فترات موحد قبل المخزون** | `fiscal_periods` + `period_scope_closures` + `period_close_checks` + `period_events`، والفحص داخل معاملة الترحيل عبر `fn_assert_period_open` |
| D4 | **نطاق العميل/المورد: شركة أو فرع** | `scope_type` + `branch_id` مع CHECK يمنع الحالتين المتعارضتين، وقيد فريد `(scope_type, branch_id, code)` |
| D5 | **متوسط التكلفة المرجح المتحرك** | لكل (صنف، مخزن)، بدقة `numeric(18,6)` للتكلفة و`numeric(18,4)` للكمية والقيمة |
| D6 | **حجز رقم المستند عند الترحيل** | المسودة بلا رقم، والرقم يُولَّد داخل معاملة الترحيل نفسها |

| D8 | **التسويات والعكس** | الجرد يولّد مستند `ADJUSTMENT`، والعكس يولّد مستند `REVERSAL` بحركات معاكسة وتكلفة تاريخية |

| المخزون | `stock_documents` · `stock_document_lines` · `stock_movements` · `stock_balances` |
| التحويلات | `stock_transfer_receipts` · `stock_transfer_receipt_lines` |
| الجرد | `stocktakes` · `stocktake_lines` |

### قواعد البيانات المطبقة

- `search_text` مولّد + فهارس GIN trigram على كل جدول بحث (وحدات/تصنيفات/أصناف/عملاء/موردين).
- `version` + trigger `fn_touch_version` على الجداول القابلة للتعديل.
- الحركات `stock_movements` **غير قابلة للتعديل أو الحذف** (trigger).
- المستند المرحّل **لا يمكن تعديل بياناته الأساسية أو حذفه**، وسطوره مقفلة (trigger).
- الجرد المرحّل وسطوره مقفلة.
- `stock_documents.doc_no` فريد داخل الفرع `(branch_id, doc_no)`، و`reversal_of_id` فريد جزئيًا لمنع العكس المزدوج.
- `fn_stock_apply` يطبّق الحركة ويحسب المتوسط داخل معاملة واحدة وبقفل صف على الرصيد.
- `fn_period_is_closed` / `fn_assert_period_open` يفحصان إغلاق الشركة أو الفرع للوحدة المطلوبة.

## 3. منطق الأعمال المنفَّذ

| العملية | القواعد |
|---|---|
| استلام (RECEIPT) | كمية > 0، تكلفة ≥ 0، تحديث المتوسط المرجح؛ تكلفة الصف النهائية تُحسب من محرك الترحيل |
| صرف (ISSUE) | التكلفة = المتوسط الساري؛ يُرفض إذا كان الرصيد لا يكفي و`allow_negative_stock = false` |
| تحويل (TRANSFER) | خروج من مخزن المصدر فقط عند الترحيل، ودخول عند الاستلام؛ دعم استلام جزئي متعدد؛ منع تجاوز المتبقي |
| رصيد افتتاحي (OPENING) | حركة دخول بتكلفة محددة صريحة |
| تسوية (ADJUSTMENT) | اتجاه لكل سطر (IN/OUT)؛ تُستخدم من الجرد |
| عكس (REVERSAL) | مستند جديد بحركات معاكسة وتكلفة تاريخية؛ لا يُعكس تحويل أو مستند عكس؛ لا يُعكس المستند مرتين |
| ترحيل الجرد | فروق فقط؛ موجب ← دخول، سالب ← خروج؛ لا ترحيل بلا فروق؛ يربط مستند التسوية بالجرد |
| إغلاق فترة | فحوصات: مسودات، أرصدة لا تطابق الحركات، تحويلات لم تُستكمل، جلسات جرد لم تُرحّل، أرصدة بتكلفة صفر، فروع غير مغلقة (للنطاق الشركة)، ثم إغلاق/إعادة فتح مع سبب إلزامي وسجل `period_events` |
| سبب فرق الجرد | إلزامي عند وجود فرق (تحقق في الخدمة + Trigger في قاعدة البيانات `STOCKTAKE_REASON_REQUIRED`) ويُحفظ في `stocktake_lines.reason` |
| الحقول المخصصة | للفروع والمخازن والأصناف والعملاء والموردين؛ تُعرَّف من شاشة الحقول المخصصة وتظهر تلقائيًا في نماذج الأصناف/العملاء/الموردين |
| عزل الفروع | كل خدمة تفحص `CanAccessBranch`، والاستعلامات تُفلتر بـ `AllowedBranchIds` |
| الصلاحيات | Default-Deny عبر `AppRegistry` لكل شاشة وزر (ترحيل/عكس/استلام/إغلاق/فتح) |

## 6. قيود معروفة (مقصودة في هذه المرحلة)

- **شركة واحدة**: لا `tenant_id` ولا RLS (قرار D1).
- لا فواتير مبيعات/مشتريات ولا قيود محاسبية؛ محرك الفترات جاهز لاستقبالها.
- لا سيريالات/دفعات/تواريخ صلاحية للأصناف، ولا باركود مرجّح لأكثر من وحدة في شاشة واحدة.
- جرد ينشئ صفوفًا لكل الأصناف النشطة في المخزن (مناسب للمخازن المتوسطة؛ للمخازن الضخمة يُنصح بجرد انتقائي لاحقًا).
- كارت الصنف يستخدم `OFFSET` (مفلترًا بالصنف) وليس Keyset؛ يُراجع عند ملايين الحركات.
- الأسعار في `item_units` مرجعية فقط ولا تدخل في تكلفة المخزون.
- لا توجد واجهة لتعديل `stock_balances` مباشرة (وهذا مقصود: كل تغيير حركة)، لكن صلاحية `UPDATE` على الجدول ما زالت ممنوحة لدور التطبيق على مستوى قاعدة البيانات.
- فلاتر شاشة الفترات: بحث + حالة؛ فلترة الفروع/الوحدات تتم من داخل شاشة التفاصيل.
- اختبار الواجهة تم عبر HTTP Smoke (تسجيل دخول + فتح كل شاشة = 200)، ولا يوجد Playwright بعد.
