# دليل التشغيل والإطلاق والتراجع (المرحلة 7)

> مرجع تنفيذي مختصر. الأوامر مكتوبة لـ Docker/systemd؛ عدّلها حسب بيئتك.

## 1) قبل النشر (مرة واحدة لكل بيئة)

1. **الأسرار**: `Jwt__Key` (64+ عشوائي)، `Bootstrap__SuperAdminPassword`، `Database__*` — من Secrets لا من ملف.
2. **مستخدم التشغيل** `ubp_app` (بلا DDL) + **مستخدم الترحيل** منفصل (DDL).
3. `Database:AutoMigrate=false` في الإنتاج.
4. `DataProtection__KeyRingPath` على قرص دائم (وإلا بطلت الجلسات عند كل إعادة تشغيل).
5. `Outbox:Enabled=true` و`Bi:Enabled=true` (أو أوقفهما مؤقتاً في أول إطلاق).

## 2) خط النشر

```bash
# 1) ترحيلات أولاً (بلا تشغيل الويب)
dotnet Ubp.Web.dll --migrate          # MIGRATIONS_OK ... → exit 0

# 2) ثم تشغيل النسخة الجديدة
docker compose up -d app             # أو systemctl restart ubp
```

- إذا خرج `--migrate` بالرمز **1** → **لا تنشر**؛ اقرأ `MIGRATIONS_FAILED error=…`.
- فحص ما بعد النشر: `GET /health/live` (200 دائماً) و`GET /api/v1/system/health` (200/503).
- شاشة `/admin/system-health` تؤكد: صفر ترحيلات معلّقة + آخر نسخة احتياطية.

## 3) النسخ الاحتياطي (خارج التطبيق)

```bash
# cron يومي 02:00
pg_dump "$NEON_DIRECT_URL" -Fc -f /backups/ubp-$(date +%F).dump && \
psql "$NEON_DIRECT_URL" -c "select fn_record_backup('SUCCESS','FULL','ubp-$(date +%F).dump',\
  $(stat -c%s /backups/ubp-$(date +%F).dump), $SECONDS)"
```
- عند الفشل: `fn_record_backup('FAILED','FULL',null,0,$SECONDS,'<reason>')`.
- التطبيق **لا ينفّذ** pg_dump ولا أوامر نظام؛ يقرأ `backup_log` فقط.

## 4) اختبار الاستعادة (ربع سنوي)

1. أنشئ قاعدة مؤقتة: `createdb ubp_restore`.
2. `pg_restore -d ubp_restore /backups/ubp-<date>.dump`.
3. `Database__MigrationConnectionString=<restore>` + `--migrate` (يجب أن تكون الترحيلات صفرية).
4. سجّل النتيجة في `backup_log` (kind = `DATA`) واختبر دخول مستخدم + تقرير واحد.

## 5) التراجع (Rollback)

| الحالة | الإجراء |
|---|---|
| فشل النشر قبل الترحيل | أعد تشغيل النسخة السابقة — لا تغيير في القاعدة. |
| فشل بعد ترحيل **إضافي فقط** (جداول/أعمدة جديدة) | أعد النسخة السابقة؛ الترحيلات الإضافية لا تكسر القديمة. |
| ترحيل **غير متوافق** (حذف/تغيير نوع) | استعادة النسخة الاحتياطية السابقة + إعادة تشغيل النسخة القديمة (خطة B). |
| بيانات خاطئة بعد النشر | أوقف الكتابة (صيانة)، استعد النسخة، أعد الترحيلات، ثم شغّل. |

> قاعدة صارمة في المشروع: **لا تعديل على ترحيل منفَّذ**، وكل تغيير جديد بسكريبت مرقّم — لذلك التراجع
> يعتمد على الترحيلات الإضافية أو استعادة نسخة، لا على "تعديل" سكريبت.

## 6) تحصين الدخول (7E)

- Rate Limiter مدمج: **10 محاولات/دقيقة لكل IP** على `/auth/*` و`/api/v1/auth/*`، والفائض يُرجع **429**.
- الحساب يُقفل بعد `MaxFailedAttempts` (الإعدادات) مع تسجيل `LOGIN_FAILED` في `audit_log`.
- لأكثر من سيرفر: استخدم مضاد وكيل موثوق (`ForwardedHeaders`) وإلا صار العدّ لكل IP وسيط واحد.

## 7) قائمة الإطلاق التجريبي (7F)

- [ ] تشغيل موازٍ ليومين على بيانات حقيقية (قراءة فقط) ومقارنة 3 تقارير مع النظام القديم.
- [ ] استيراد الأرصدة الافتتاحية عبر `/admin/import-tool`: **معاينة** أولاً (صفر أخطاء + متوازن)، ثم تنفيذ.
- [ ] تدريب مستخدمين على: الدخول، تغيير كلمة المرور الإجباري، نقطة البيع، الحجز، التقارير.
- [ ] التأكد من: `backup_log` يعمل، `/admin/system-health` صحي، صندوق الرسائل يعالج الرسائل.
- [ ] تعطيل `Outbox`/`Bi` إن أردت إطلاقاً بأقل متغيرات، ثم تفعيلهما تدريجياً.
