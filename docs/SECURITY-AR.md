# مراجعة الأمان — Universal Business Platform (platform-v2)

**النطاق:** النسخة الحالية (المرحلة الأولى) · **آخر تحديث:** 2026-10-19

---

## 1. نموذج التهديد المختصر

| التهديد | الضابط المطبّق |
|---|---|
| دخول غير مصرح | كلمة مرور BCrypt + قفل حساب + رسالة موحّدة |
| تخمين كلمات المرور | حد محاولات + مدة قفل قابلة للضبط من الإعدادات |
| سرقة جلسة | كوكي HttpOnly + SameSite=Lax + جلسة سيرفر + انتهاء خمول |
| سرقة Refresh Token | تخزين Hash فقط + HttpOnly + تدوير + إلغاء عند الخروج |
| تصعيد صلاحيات | Default-Deny + فحص مركزي في الخدمات + منع غير Super Admin من أعلام المدير |
| الوصول لفرع آخر | فحص `AllowedBranchIds` في كل خدمة/استعلام + فحص الجلسة |
| حقن SQL | Dapper Parameterized + قائمة فرز بيضاء + أسماء جداول مسموحة |
| XSS | Blazor يرمّز المخرجات افتراضياً؛ لا `MarkupString` لمدخلات المستخدم |
| CSRF | Antiforgery على كل نماذج الدخول/الخروج/تبديل الفرع واللغة |
| كشف تفاصيل الخطأ | صفحة خطأ عامة + Trace ID فقط + Serilog داخلي |
| تسريب أسرار في Audit | استبعاد `password_hash` و`token_hash` و`password` |
| تعديل/حذف السجل | Triggers ترفض UPDATE/DELETE على `audit_log` |
| حذف آخر Super Admin | Trigger + فحص في الخدمة |
| مخزن لا يتبع فروع المستخدم | Triggers على `user_branches`/`warehouse_branches`/`user_warehouses` |
| تشغيل اختبارات على الإنتاج | مقارنة اتصال QA بconnection التطبيق + فشل آمن |
| هجمات القوة على API | JWT قصير + Rate limiting (يُنصح بإضافته على الـ Proxy) |
| تسريب Connection String | يُقرأ من Secrets/ENV، وشاشة قاعدة البيانات لا تعرضه |

## 2. الصلاحيات

- الشاشات والأزرار معرفة في `AppRegistry` بأكواد ثابتة (`screen_code`, `action_code`).
- الصلاحية = أدوار + استثناءات فردية؛ الاستثناء الفردي يتغلب على الدور.
- النطاق: 0 سجلاتي / 1 فروعي / 2 الكل.
- كل خدمة تستدعي `PermissionService.RequireAsync` قبل أي عملية.
- الواجهة تخفي الأزرار غير المسموحة، لكن **التحقق الحقيقي على السيرفر**.
- الأدوار المعطلة لا تُحتسب. المستخدم المعطل لا يستطيع الدخول ولا تستمر جلسته.
- `Super Admin` لا يظهر إلا لـ Super Admin آخر، ولا يمكن تعديله من أدمن عادي.

---

## 3. عزل الفروع

- الجلسة تخزن الفرع الحالي، ويُعاد التحقق من عضويته في كل طلب.
- استعلامات الفروع/المخازن/المستخدمين/السجل تُفلتر بـ `branchIds` للمستخدم غير الأدمن.
- `WarehouseRepository` يدعم نطاق «سجلاتي» (مخازن المستخدم) و«فروعي» (مخازن الفروع).
- عند إزالة فرع من مستخدم، يمنع Trigger أي مخزن سيصبح بلا فرع.
- الأدمن يتجاوز قاعدة الفرع ويمكنه الدخول بدون فرع، وهذا مقصود.

---

## 4. إدارة الأسرار

- `Jwt:Key` يجب أن يكون 32 حرفاً على الأقل، ويُحقن من Secrets في الإنتاج.
- `Database:ConnectionString` لمستخدم `ubp_app` (لا DDL).
- `Database:MigrationConnectionString` لمستخدم DDL، ولا يُستخدم في التشغيل العادي.
- `Bootstrap:SuperAdminPassword` يجب تغييره أو إزالته بعد أول تشغيل.
- لا توجد أسرار في المستودع؛ `appsettings.json` للتنمية فقط.
- يُنصح بتدوير JWT Key واعتبار كل التوكنات ملغاة عند التدوير.

---

## 5. السجلات والتتبع

- Serilog يسجل Trace ID في كل طلب (Header `X-Trace-Id`).
- الأخطاء غير المتوقعة: المستخدم يرى صفحة عامة + Trace ID، والتفاصيل في السجلات.
- `audit_log` يسجل: INSERT/UPDATE/DELETE، LOGIN/LOGOUT/LOGIN_FAILED،
  PERMISSION_CHANGE، PASSWORD_RESET، MIGRATION.
- لا تُسجَّل كلمات المرور أو التوكنات أو الـ Hashes.
- يُنصح بإرسال السجلات إلى وجهة مركزية (Seq/Elastic) في الإنتاج.

---

## 6. قاعدة البيانات

- الترحيلات بسكريبتات مرقمة فقط، وكل سكريبت داخل معاملة.
- لا يوجد DDL من الواجهة؛ شاشة قاعدة البيانات تعرض/تعدّل بيانات فقط.
- الحذف المباشر ممنوع إذا كانت هناك ارتباطات؛ الواجهة تحوّل الحذف إلى تعطيل.
- `app_settings` صف واحد مضمون بفهرس Unique على `(true)`.
- `currencies.is_base` عملة واحدة بفهرس Unique جزئي.
- `users.username` فريد بـ `lower(username)`.
- البحث العربي عبر دالة `IMMUTABLE` + فهارس GIN.

---

## 7. قائمة تحقق قبل الإنتاج

- [ ] تغيير كلمة مرور Super Admin وحذف القيمة الافتراضية.
- [ ] JWT Key عشوائي 64+ حرفاً من Secrets.
- [ ] `Database:AutoMigrate=false` وتنفيذ الترحيلات من CI/CD.
- [ ] HTTPS + HSTS خلف Reverse Proxy موثوق.
- [ ] تقييد الوصول لقاعدة البيانات بـ IP/Firewall.
- [ ] مستخدم DDL منفصل وغير متاح للتطبيق.
- [ ] قاعدة QA منفصلة تماماً وبيانات اصطناعية.
- [ ] نسخ احتياطي آلي + اختبار استعادة.
- [ ] مراجعة صلاحيات الأدوار قبل إنشاء المستخدمين.
- [ ] إضافة Rate Limiting على `/auth/login` و`/api/v1/auth/*` في الـ Proxy.
- [ ] مراقبة `LOGIN_FAILED` و`PERMISSION_CHANGE` وإعداد تنبيهات.
- [ ] تفعيل تدوير السجلات وسياسة الاحتفاظ.

---

## 8. مخاطر متبقية

1. **لا يوجد MFA** بعد.
2. **Rate limiting غير مدمج** داخل التطبيق (يُنصح به على الـ Proxy حالياً).
3. **إعادة استخدام Refresh Token** لا تُكتشف بعد (Rotation موجودة، Reuse Detection لاحقاً).
4. **الشركة الواحدة** لكل قاعدة بيانات: العزل بين الشركات يعتمد على نشر منفصل.
5. **تعديل الصفوف JSON** في شاشة قاعدة البيانات قوي لكنه يحتاج انضباطاً ومراجعة بشرية.
