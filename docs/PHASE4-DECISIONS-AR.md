## 2) القرارات الجديدة (N) — مبنية على مراجعة الكود الفعلي

| # | القرار | السبب (من الكود) | الأثر |
|---|---|---|---|
| **N1** | `app_settings` تبقى صفاً واحداً بأعمدة مُصنّفة؛ لا Key/Value | `0003:4-21` + `ux_app_settings_singleton` + 4 طبقات مرتبطة | صفر إعادة كتابة |
| **N2** | `posting_defaults` تُوسَّع بـ`party_type`، ويُنشأ `posting_default_types`؛ **كل مرحلة تضيف مفاتيحها في migration مستقل** | `0020:120-131` موجود + قاعدة G1 | لا تعديل لـ`0024` لاحقاً |
| **N3** | فحص الاكتمال عبر `IModulePostingReadiness` مخبأ في `IMemoryCache` ويُمسح عند تعديل الإعدادات | حجب كل ترحيل بسبب مفتاح لموديول غير مبني = تعطيل النظام | لا تعطيل للمخزون الحالي |
| **N4** | **توقيت التكلفة:** إذن الصرف/التنفيذ يُثبت `Dr COGS / Cr Inventory` بتكلفة FEFO؛ الفاتورة تُثبت `Dr Customer / Cr Revenue + VAT` | يجب أن يُطابق تقرير «المخزون مع الأستاذ»؛ المخزون ينقص عند خروج البضاعة | هامش مؤقت سالب بين التسليم والفاتورة → تقرير «تسليمات بلا فاتورة» |
| **N5** | **الضريبة:** تُحسب لكل بند `round(net × rate, 2)` وتُجمع؛ فرق الإجمالي إلى `rounding_difference` | تقريب الإجمالي يخلّ بالتوازن | قيد متوازن دائماً |
| **N6** | **الجدول الموحد** `commercial_documents` بعمودين `customer_id`/`supplier_id` + `CHECK` واحد فقط منهما | FK حقيقي إلى الجدولين (لا polymorphic) | سلامة مرجعية كاملة |
| **N7** | **تكامل المخزون:** الفاتورة/الإذن يُرحّل **مستند مخزون داخلي** (`stock_documents`) ويُخزّن `stock_document_id`؛ لا تعديل على `stock_movements` | `stock_movements.document_id → stock_documents NOT NULL` (`0016:56`) | إعادة استخدام المحرك المُختبر (52 اختباراً) |
| **N8** | `stock_lots` يحتوي `unit_cost`؛ فهرس FEFO `(item_id, warehouse_id, expiry_date, id) WHERE quantity_on_hand > 0`؛ `items.track_expiry` | تكلفة الدفعة لازمة لـCOGS، والأصناف غير المتتبعة يجب ألا تدخل Lots | أداء + دقة تكلفة |
| **N9** | **Backfill** في نفس migration: دفعة اصطناعية لكل (صنف، مخزن) بـ`expiry=NULL` و`unit_cost=average_cost` و`qty=on_hand` | بدونها أول صرف لا يجد دفعة | لا كسر للأرصدة |
| **N10** | `warehouses.warehouse_type ('MAIN','CONSUMABLES')` + فهرس فريد جزئي: مخزن مستهلكات واحد لكل فرع | `0003:42-56` بلا نوع؛ D14 يحدد مخزن المستهلكات | استهلاك الخدمات يصبح ممكناً |
| **N11** | مصدر الحجز الوحيد `stock_lots.quantity_reserved`، و`stock_balances.reserved_qty` **كاش** يُحدَّث في نفس المعاملة | تجنّب مصدرين للحقيقة | اتساق + سرعة العرض |
| **N12** | `document_allocations` (source_document → target_document, amount, kind) لتخصيص الدفعات المقدمة والتحصيل | D5 يحتاجه؛ `voucher_allocations` وحده لا يكفي | تقارير أعمار دقيقة |
| **N13** | **لا `audit_logs`**؛ يُستخدم `audit_log` القائم ويمدّد `CHECK(action)` بـ`POST`/`REVERSE` | `0005:4-18` + `AuditSanitizer` + Triggers عدم التعديل | لا ازدواج ولا فقدان حجب الأسرار |
| **N14** | Control DB تخزّن `database_name` فقط (بلا كلمات مرور لكل عميل)؛ الاتصال من سر واحد؛ ولو لزم التشفير → AES-GCM بمفتاح بيئي | المفتاح بجوار البيانات = تشفير بلا حماية | تقليل سطح الهجوم |
| **N15** | النسخ الاحتياطي **job خارجي** يكتب `backup_log`؛ الشاشة تقرأ السجل | `pg_dump` غير موجود في صورة التشغيل (`Dockerfile`) | لا فشل تشغيلي صامت |
| **N16** | `bi` = **Materialized Views** + `ALTER DEFAULT PRIVILEGES` + `REFRESH` مجدول؛ اللوحة تعتمد `sales_daily_totals` | الـView لا يحسب مسبقاً | تحقق < 500ms/< 300ms |
| **N17** | كاتب XLSX يدوي: OOXML (sheet + sharedStrings) داخل ZIP بـ`System.IO.Compression` | `System.IO.Packaging` غير موجودة في .NET 10 shared framework | صفر حزم |
| **N18** | `status` للجداول الجديدة **lowercase**؛ الجداول القديمة تبقى كما هي مع طبقة تحويل في الواجهة | `stock_documents` uppercase (`0016:14`) و`journal_entries` lowercase | توثيق صريح بدل الافتراض |
| **N19** | FK البند باسم `document_id` (لا `header_id`) | `stock_document_lines.document_id` و`journal_entry_lines.entry_id` | اتساق التسمية |
| **N20** | الصلاحيات `module.screen.action`، وفعل واحد لكل معنى (`create` للإنشاء، `save` للحفظ) بلا مترادفات | `SETTINGS_GENERAL/EDIT` موجود والخطة تقترح `save` | لا صلاحيتين لنفس الزر |
| **N21** | `message_outbox`: `next_attempt_at`, `dedupe_key UNIQUE`, `provider_message_id`, احتفاظ 90 يوماً | إعادة الإرسال بعد restart | لا رسائل مكررة |
| **N22** | `notifications`: `CHECK (user_id IS NOT NULL OR role_id IS NOT NULL)` + فهرس `(user_id, is_read)` | جرس + عدّاد سريع | أداء + سلامة |
| **N23** | `saved_report_filters`: `UNIQUE(user_id, report_key, filter_name)` + حد 8KB + تحقق `report_key` من AppRegistry | منع تكرار/تضخيم | جودة بيانات |
| **N24** | حارس مرتجع: `sum(returned_qty) ≤ original_line.qty` عبر Trigger | نفس نمط استلام التحويلات | لا مرتجع زائد |
| **N25** | كل مستند جديد يفحص الفترة عبر `fn_assert_period_open(..., 'ACCOUNTING')` داخل نفس المعاملة | المرحلة 3 تبني هذا | لا ترحيل في فترة مغلقة |
| **N26** | أنواع المستندات في `document_sequences` تطابق `^[A-Z][A-Z0-9_]*$` وبطول ≤ 30 | `0011:24-26` قيد موجود | لا فشل ترقيم |

## 3) ما أُعيد من النسخة السابقة (طلب صريح)

| البند | كان | صار |
|---|---|---|
| D4 فاتورة تلقائية عند التنفيذ + تجميع | ملغى | إعدادان جديدان + اختبار «تنفيذ بلا فاتورة» |
| حد المبيعات | ملغى | `credit_limit` قائم + `customer_branch_limits` (4A-1) |
| شاشة المواعيد اليومية + صلاحيتها | غائبة عن الجدول | `sales.appointments.view` + `/sales/appointments` |
| شاشة إدارة الخزائن + صلاحياتها | غائبة | `treasury.management.view/edit` + `/treasury/management` |
| `commission_basis` | مُستشهد به وغير موجود | عمود في `app_settings` (migration 4F) + الشاشة |
| D15 أنماط كمية المستهلك + بدائل | ملغى | `consumption_mode` + `recipe_substitutes` |
| سجل إسناد الحجز التاريخي | ملغى | `booking_assignments` |
| D24 عملة واحدة | ملغى | مُعاد نصاً |
| `sales.commissions.calculate` | غائب | صلاحية + تقرير `/sales/commissions` |
| `control.tenants.run_migrations` | غائب | صلاحية + زر ترقية عميل |
| `reserve_stock_on_booking` / `appointment_slot_minutes` / `pos_receipt_footer` / `auto_follow_up_overdue` | ملغاة | مُعادة كإعدادات مُصنّفة **مع مستهلك فوري لكل واحد** |

> **قاعدة الإعداد الميت:** أي إعداد يُضاف يجب أن يكون له **مستهلك** في نفس الجزء أو الجزء التالي مباشرة، وإلا يُؤجَّل. هذا يمنع تكرار مشكلة «إعدادات بلا مستهلك».

## 4) القرارات المفتوحة المتبقية (تحتاج توقيعك)

| # | القرار | التوصية | أثر البديل |
|---|---|---|---|
| **O1** | D1: تعدد العملاء الآن أم تجميده؟ | **تجميد D1 للإطلاق الأول** (عميل واحد) + تنفيذ 7A-0 بعد الإطلاق. سبب: refactor طبقة الاتصال يُعيد اختبار 75 اختباراً ويؤخر الإطلاق بلا قيمة تجارية أولى | تنفيذ 7A-0 الآن: +3 أيام ومخاطر تراجعية، لكن يفتح بيع SaaS مبكراً |
| **O2** | توجيه العميل (إن نُفِّذ): Subdomain أم Header؟ | **Subdomain** (أنظف أمنياً، ولا يحتاج عميلاً يضبط Header) | Header أسرع للاختبار لكنه يعرّض للتلاعب ويحتاج تثبيت من الـproxy |
| **O3** | `commission_basis` في 4F | **نعم** — migration 4F يضيف العمود + الشاشة (1=net, 2=gross, 3=collected) | حذف الإشارة من 4F وفقدان مرونة سياسة العمولة |
| **O4** | حدود مبيعات فرعية | **نعم** — `customer_branch_limits` (حد لكل عميل/فرع) فوق `credit_limit` | الاعتماد على `credit_limit` فقط (أقل دقة للمتعدد الفروع) |
| **O5** | D15 كامل (3 أنماط + بدائل) | **نعم** — التكلفة ~60 سطراً وقيمة تشغيلية عالية | «صرف آلي فقط» يبسّط لكنه يفشل عند نقص مستهلك |
| **O6** | تصميم الطرف في الجدول الموحد | **N6** (عمودان + CHECK) | polymorphic بلا FK = فقدان سلامة مرجعية |
| **O7** | النسخ الاحتياطي | **N15** (job خارجي + `backup_log`) | `pg_dump` داخل التطبيق يحتاج تعديل صورة Docker + صلاحيات volume |
| **O8** | أداة اختبار الحمل (7F) | **harness .NET داخل المستودع** (HttpClient + WebSocket) — لا حزم ولا بنية إضافية | k6/artillery خارجي: أقوى لكنه أداة جديدة خارج الستاك |

> **قرار افتراضي عند عدم الرد:** تُطبَّق التوصية، وتُوثَّق بـ«اعتُمد افتراضياً في تاريخ …». لا يبدأ أي جزء يعتمد على قرار مفتوح قبل حسمه.
