## 2. قرارات التصميم المهمة

1. **Blazor Server** بدل SPA منفصل: كل الكود C#، الصلاحيات تُفحص في نفس العملية،
   ولا حاجة لمزامنة حالة بين متصفح وAPI. الـ API موجود للمصادقة والتكامل.
2. **Dapper + SQL صريح** بدل ORM: السيطرة الكاملة على `LIMIT 25`، Keyset، والفهارس.
3. **جلسة على السيرفر** (`user_sessions`) وليس في الكوكيز: تبديل الفرع وانتهاء الخمول
   يُفحصان على السيرفر، والكوكي يحمل معرف الجلسة فقط.
4. **الجلسة القصيرة + Refresh Token هاش فقط**: لا يُخزَّن التوكن الأصلي في قاعدة البيانات.
5. **Triggers لحماية التناسق** بين `user_branches` و`user_warehouses` و`warehouse_branches`،
   مع استثناء الحذف المتسلسل عند حذف المستخدم/المخزن.
6. **Audit غير قابل للتعديل** على مستوى قاعدة البيانات، وليس مجرد اتفاق في الكود.
7. **الحد 25 في طبقة البيانات**: `PageRequest.SafePageSize` + `LIMIT` في كل استعلام.
8. **بحث عربي موحّد في SQL** (`normalize_search`) ليعمل مع الفهرس GIN وليس في الذاكرة.

## 3. تدفق الدخول

```
POST /auth/login (Antiforgery)
  → التحقق من المستخدم + قفل الحساب + BCrypt
  → إنشاء Refresh Token (Hash) + Session (branch, expiry)
  → Cookie ubp_auth (claims: user, session, admin flags)
  → Cookie ubp_refresh (HttpOnly, path=/auth)
  → Audit LOGIN
  → Redirect /
```

- كل طلب HTML بعد ذلك يمر بـ `SessionValidationMiddleware`: يتحقق من الجلسة،
  يمددها عند النشاط، ويتأكد أن الفرع الحالي ضمن فروع المستخدم.
- API يستخدم JWT قصير (15 دقيقة) ويمكن تجديده من `/api/v1/auth/refresh`.
- الخروج يلغي الجلسة **وكل** Refresh Tokens للمستخدم.

## 5. قيود معروفة (بصراحة)

1. **شركة واحدة لكل نشر** حالياً (لا `tenant_id`). الاسم «متعدد المستأجرين» في الرؤية الأصلية،
   لكن المرحلة الأولى تفترض نشراً منفصلاً لكل شركة. إضافة `tenant_id` + RLS هي الخطوة التالية.
2. **Audit log غير مقسّم (Partitioned)** بعد؛ Keyset يغطي الأداء حتى ملايين الصفوف،
   لكن التقسيم الشهري مطلوب لاحقاً.
3. **نتائج QA** تُحفظ في قاعدة التطبيق (`qa_*`) بينما قاعدة الاختبار منفصلة.
   الفصل الكامل لقاعدة النتائج ممكن في مرحلة لاحقة.
4. **لا يوجد بعد**: البريد/الإشعارات، 2FA، استيراد/تصدير، شاشات ERP التشغيلية،
   محرك ترحيل محاسبي، وRBAC على مستوى الحقول.
5. **Refresh Token**: التدوير موجود، لكن كشف إعادة استخدام التوكن المسروق (Reuse Detection)
   يحتاج تسجيل عائلة التوكنات.
6. **إدارة الصفوف** في شاشة قاعدة البيانات تسمح بتعديل JSON مباشر (مخصصة للمدير الأعلى)،
   وليست نموذجاً مرئياً لكل عمود.

## 6. الخطوة التالية المقترحة

1. إضافة `tenant_id` + PostgreSQL RLS + اختبار عزل مستأجرين.
2. بناء أول شريحة ERP: المنتجات → المخزون → فاتورة بيع → قيد محاسبي.
3. قواعد ترحيل محاسبية (`accounting_posting_rules`) وفترات مقفلة.
4. Playwright لسيناريوهات الواجهة + بوابات جودة في CI.
5. تقسيم `audit_log` شهرياً + سياسة احتفاظ.
